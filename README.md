# 과거형 숲

초등학생용 불규칙동사 68개 현재형 → 과거형 학습 게임. React 18, Vite, TypeScript, Zustand, IndexedDB(idb-keyval). 데이터 원본은 사용자 첨부 텍스트의 JSON을 그대로 보존했다. SharePoint 문서는 접근 실패로 대조하지 못했다.

## 실행

- `npm install`
- `npm run dev`
- `npm test`
- `npm run build`
- HTTPS 배포 후 최초 온라인 접속에서 서비스 워커 설치가 완료되면 앱 셸·글꼴·에셋을 캐시한다. 이후 학습 기능은 외부 요청 없이 동작한다.
- 기기 내 저장만 사용한다. 브라우저 저장 데이터를 지우면 기록이 사라진다. 별도 회원가입·서버·분석·광고가 없다.
- 영어 음성이 있는 기기에서만 발음/듣기 게임을 제공한다. 브라우저 음성은 기기에 따라 오프라인에서 사용할 수 없을 수 있다.

## 화면

1. 탐험 지도: 10개 가족, 순차 해금, 나무 성장 4단계, 복습, 연속 학습, 주간 5일 목표, 퀘스트
2. 가족 규칙 안내
3. 현재형/과거형 뒤집기 카드
4. 미니게임 7종: 두 선택지, O/X, 짝 맞추기, 빈칸 타일, 전체 타일, 듣기, 거꾸로
5. 보스 퀴즈: 해당 구역 전체 단어, 첫 응답 기준 80% 통과
6. 결과: 별, 도토리, 다음 판/지도
7. 동물 도감: 보스 10마리와 숨은 동물 10마리
8. 숲 꾸미기: 12개 소품 구매와 지도 배치
9. 보호자 PIN 설정/입력
10. 보호자 기록/설정: 학습 시간, 가족별 숙련도, 오답 10개, 전체 68개, 목표/도전 모드, 2단계 초기화

## 그림 생성

`cp .env.example .env` 후 개인 Higgsfield API 키를 입력한다. 키를 커밋하지 않는다.

- `npm run assets -- --plan`: 63개 정적 그림의 생성 계획만 출력
- `npm run assets`: 기존 파일을 건너뛰고 순차 생성
- `npm run assets -- --force`: 기존 그림 재생성
- 생성 후 `npm run build`로 에셋 목록을 다시 반영한다.

공식 TypeScript SDK `@higgsfield/client/v2`를 사용한다. 공식 SDK README에서 확인한 `flux-pro/kontext/max/text-to-image` endpoint를 쓴다. 제출 후 5초부터 최대 30초 간격으로 폴링하고 에셋별 대기 제한은 10분이다. 서버가 명시적으로 실패한 생성만 최대 2회 재시도한다. 제출 결과 불명확·폴링 통신 실패·다운로드 실패는 중복 비용 방지를 위해 자동 재제출하지 않는다. request_id를 확인한 뒤 재개한다. 완성된 결과를 즉시 내려받고 manifest.json에 기록한다.

예상 시간은 63장의 순차 생성이므로 장당 1~3분일 때 약 1~3시간이며 모델 대기열에 따라 더 걸릴 수 있다. 생성 비용은 계정과 모델 정책에 따른다. 런타임 앱은 Higgsfield API를 호출하지 않는다. 선택사항인 cheer.mp4는 생성하지 않았다.

## 결정 기록

- 문서 앞의 ‘5장’보다 상세 에셋 표를 우선해 정적 이미지 63장을 계획했다. 사용자가 승인한 기존 플러그인 생성 토리 1장을 홈에 반영했다. 나머지 62장은 미생성이다. 이후 신규 생성은 Higgsfield API만 사용한다. Sites의 새 비밀키는 조회할 수 없어 현재 로컬 스크립트에 전달되지 않았다.
- 3개 단어만 있는 가족의 짝꿍 찾기는 새 단어를 추가하지 않고 3쌍을 쓴다. 다른 가족은 최대 4쌍. 나머지 미니게임은 보통 5~6문제로 구성한다.
- 보스는 선택형 대신 타일 완성형을 사용한다. 그 구역의 모든 단어를 처음에 1회씩 묻고, 오답은 끝에서 1회 재연습하되 통과율을 부풀리지 않는다.
- be는 판정 함수에서 was/were 모두 허용한다. 타일 문제는 was 제작을 명시한다.
- 오답을 같은 날 다시 맞혀도 다음 날 복습에 남긴다. 상자 이동과 다음 날 복습 조건을 함께 적용한다.
- 나무 단계는 구역 평균 상자 수준에 따라 0%, 35% 미만, 75% 미만, 75% 이상으로 나눈다.
- 퀘스트는 날짜에 따라 정답 수·콤보·판 수 목표를 바꾼다. 잠긴 구역이나 없는 음성을 요구하지 않는다.
- 숲 꾸미기는 구매 후 지도 아래 자동 배치한다. 드래그 배치는 문서에 없어 추가하지 않았다.
- 별은 최초 응답 정답률 기준으로 60%/80%/100%이며, 구역 지도는 가장 높은 보스 별 점수를 보존한다.
- PIN은 기기 내 실수 방지용 잠금이며 암호화 보안 기능이 아니다. 초기화해도 PIN은 보존한다.
- 수동 결과 이동으로 피드백 읽을 시간을 보장한다. 정답 효과 0.6초, 전환 0.25초, 모션 줄이기 설정 대응.

## 검증 상태

- 자동 테스트: 데이터/정답과 was·were/오답 보기/복습/월말·연말/콤보/별/퀘스트 147개 통과.
- TypeScript 컴파일과 Vite 빌드 확인. 최종 빌드에 API 키 관련 문자열이 없는지 확인한다.
- 그림 없이 동작하도록 에셋 manifest를 검사하고 대체 아이콘을 사용한다.
- 390×844 및 820×1180을 고려한 반응형 CSS 작성. 모든 터치 버튼 최소 56px.
- 이 환경에서 Sites 지정 브라우저 제어 스킬을 사용할 수 없어 실제 브라우저 클릭 검사, 화면 캡처, 비행기 모드 재실행 검증은 **미실행**이다. 자동 테스트 결과를 해당 검증의 대체 증거로 주장하지 않는다.
- WebMCP 진행 조회 도구는 기능 감지 방식으로 구현. 지원 브라우저 검증은 미실행.

## 확인할 결정 3개

1. 상세 목록의 63개 그림 생성 및 모델 비용을 적용할지.
2. 현재 3쌍인 소규모 가족의 짝꿍 게임을 그대로 유지할지.
3. 보스 시험을 타일 완성형으로 유지할지, 키보드 직접 입력으로 바꿀지.

## API 연결 점검

Sites 서버에서 `/api/higgsfield/check` 경로로 읽기 전용 인증 검사를 수행한다. `X-Forest-Admin` 비밀 토큰과 Sites의 비공개 접근 검사를 모두 통과해야 한다. 저장된 Higgsfield 키는 서버 밖으로 반환하지 않는다. 어린이 학습 화면은 이 경로를 호출하지 않는다. 이 검사는 그림 생성 요청이나 비용을 발생시키지 않는다. 이후 생성 작업도 별도의 제작 단계에서만 수행한다.
